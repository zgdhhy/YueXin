# 提示词拆成可版本化的写作要求和固定的输出格式

用户要在后台调整「怎么找论文、怎么分析、怎么做视频」。但流水线依赖大模型的输出格式：解读必须是八段式并带元信息，选题精选和讲解脚本必须是指定的 JSON。所以每个环节的提示词拆成两部分：

- **写作要求**：读者定位、侧重点、语气、篇幅等。存进数据库，每次保存记一个版本。
- **输出格式**：留在代码里，用户不能改。

运行认领时，把各环节当时启用的写作要求版本写进运行配置快照（与 [ADR 0002](0002-explicit-model-policy-and-run-snapshot.md) 一致），每篇产出都记下生成它的版本。

我们没有选择「全文可改，保存时试跑校验」。原因是格式坏掉的代价是无人值守的运行整批失败；而只开放写作要求，已经能满足调整风格和侧重点的需求。
