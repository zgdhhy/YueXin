# 后台界面规范

采用方案 A「安静的阅读室」：后台以任务、内容管理与设置组织，布局与前台共享中性底色和青色强调。设计约定见 [design-scheme-a.md](design-scheme-a.md)。

## 外框与排版

- 统一浅色主题；216px 桌面侧栏，32px 内容边距；手机使用原生导航对话框与20px内容边距，适配安全区域。
- 正文14px，辅助13px，标题24–28px。石墨文字、轻边界、青色强调，取消渐变与厚阴影。
- 控件6px圆角，分区8px圆角；桌面操作至少36px，手机44px。
- 模型配置为单页：服务商分组在上（每个服务商一张卡片，模型全部展开），工作流（默认模型 + 四环节）在下，底部折叠「用量与诊断」。未确认默认模型时页面顶部显示提示条。
- 配置行内不放操作按钮：点服务商标题打开编辑服务商，点模型行打开模型弹窗，点工作流行打开对应设置。页面只保留「添加服务商」和每组的「+ 添加模型」（订阅未登录时为「登录账号」）。
- 模型行只显示名称、用途（默认 / 备用 / 单独指定的环节）与验证状态；服务商只标「已停用 / 待登录」。环节沿用默认时只写「沿用默认」，只写出与默认不同的部分。
- 测试连接、设为默认在模型弹窗内；停用、删除放在弹窗底部左侧，确认后取消回到原弹窗。保存服务商连接后自动重测其在用且验证失效的模型。
- 视觉：沿用青色强调，白卡片、12px 圆角、轻阴影，状态与用途用浅色胶囊。

## 组件约定

- 页面标题、卡片、按钮、输入、下拉和状态采用共享控件；模型页保持相同间距与控件尺寸。
- 复杂编辑使用560px右侧单层抽屉，手机全屏；固定头部和底部，内容独立滚动。
- 抽屉X、Esc、遮罩同步关闭；网络不参与关闭流程。迟到响应不得改变后开的面板。
- 草稿只保留当前页面会话内存，敏感值不写持久存储。「添加服务商」不保留草稿，每次从服务商目录开始。提交失败保留输入，明确保存后更新摘要。
- 未配置默认只提示一次，各继承环节显示等待状态。具体异常定位到相应配置。
- 站内通知不遮挡关闭或提交按钮，位置固定（桌面右上角，窄屏底部），打开弹窗不移动；成功和失败都在 1.5 秒后自动关闭，需要用户决定的事项用确认弹窗；危险操作明确确认。

## 验证

模型回归：`npx tsx scripts/check-model-ui.ts`，使用独立数据库和本机模拟推理；运行步骤见 README「浏览器回归」。截图禁用动画，避免将抽屉过渡态误作最终样式。

方案 A 布局检查：`node --experimental-strip-types scripts/check-layout.ts`。检查运行于本地3000服务，使用只读交互（不启动任务、不保存配置、不调用模型），覆盖320 / 390 / 768 / 1024 / 1440px和移动导航、目录、筛选、配置抽屉。截图与结果保存在 `data/scheme-a-review/`。
